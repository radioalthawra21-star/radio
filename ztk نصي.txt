🍃 ZKTeco Bridge Service - دليل التكامل
🍃 جهاز ZKTeco ETK-45A_ID مع Node.js
═══════════════════════════════════════════════════════════

────────────────────────────────────────────────────────
🏗️  المعمارية (Architecture)
────────────────────────────────────────────────────────

  في المكتب (Local)                    في السحابة (VPS)
  ────────────────                    ────────────────
  ZKTeco ETK-45A_ID                   السيرفر الرئيسي (Node.js)
  │ Port 4370 (UDP)                   │ MongoDB
  │                                   │
  ▼                                   │
  Bridge Service (bridge/index.js) ───► POST /api/zkteco/attendance
  │   │                               │
  │   ├── يجلب سجلات البصمات من الجهاز │
  │   └── يرسلها للخادم عبر HTTPS      │
  │                                   ▼
  │                             Attendance collection
  │
  ⏱️ دورة المزامنة: كل 30 ثانية (قابلة للتعديل)

────────────────────────────────────────────────────────
📂  ملفات المشروع (Files)
────────────────────────────────────────────────────────

  bridge/
  ├── index.js          # شغال bridge - السكريبت الرئيسي
  ├── config.js         # إعدادات الجهاز والخادم
  ├── package.json      # اعتماديات (node-zklib, axios, dotenv)
  ├── .env.example      # قالب الإعدادات
  └── .env              # إعداداتك الفعلية (لا ترفعه لـ git)

  backend/
  ├── controllers/zktecoController.js   # يستقبل البيانات من bridge
  ├── routes/zktecoRoutes.js            # route: POST /api/zkteco/attendance
  ├── server.js                         # تم تعديله لإضافة zktecoRoutes
  └── models/User.js                    # تم إضافة حقل zkUserId

────────────────────────────────────────────────────────
⚙️  إعدادات bridge (bridge/.env)
────────────────────────────────────────────────────────

  # جهاز ZKTeco
  ZK_IP=192.168.1.201          ← غير الرقم حسب IP جهازك
  ZK_PORT=4370                 ← منفذ UDP (ثابت من ZKTeco)
  ZK_TIMEOUT=5000              ← مهلة الاتصال بالجهاز

  # رابط السيرفر الرئيسي
  API_BASE_URL=http://localhost:3000
  # ⚠️ غيّره لما تنقل للسيرفر:
  # API_BASE_URL=https://your-domain.com

  API_KEY=my-secret-key        ← نفس المفتاح اللي في backend/.env

  # دورة المزامنة (بالملي ثانية)
  POLL_INTERVAL_MS=30000       ← كل 30 ثانية
  SYNC_ON_START=true           ← يسحب السجلات أول ما يشتغل

────────────────────────────────────────────────────────
🔐  مفتاح الأمان (Security)
────────────────────────────────────────────────────────

  backend/.env يحتوي على:
    BRIDGE_SECRET_KEY=my-secret-key

  bridge/.env يحتوي على:
    API_KEY=my-secret-key

  ⚠️  غير "my-secret-key" لكلمة سر قوية.
  ⚠️  bridge يرسل المفتاح في header: x-bridge-key
  ⚠️  السيرفر يتحقق من المفتاح قبل قبول البيانات.

────────────────────────────────────────────────────────
▶️  تشغيل bridge في المكتب
────────────────────────────────────────────────────────

  1- تأكد أن جهاز ZKTeco متصل على نفس الشبكة
  2- اعرف IP الجهاز (من قائمة إعدادات الجهاز)
  3- شغّل:

  cd bridge
  copy .env.example .env       # أو: cp .env.example .env
  notepad .env                 ← عدل ZK_IP و API_BASE_URL
  npm install
  node index.js

  راح تشوف:
    ✅ متصل بجهاز ZKTeco على 192.168.1.201:4370
    📊 تم جلب X سجل من الجهاز
    ✅ أرسل X سجل حضور

────────────────────────────────────────────────────────
🔄  تدفق العمل (Flow)
────────────────────────────────────────────────────────

  1. جهاز ZKTeco يخزن بصمات الموظفين وسجلات الحضور
  2. Bridge service يطلب السجلات من الجهاز (UDP port 4370)
  3. يحوّل السجلات إلى JSON
  4. يرسلها عبر HTTPS للخادم الرئيسي (POST /api/zkteco/attendance)
  5. الخادم:
     a. يتحقق من مفتاح bridge
     b. يبحث عن المستخدم عن طريق zkUserId
     c. ينشئ سجل حضور جديد أو يحدث الموجود
  6. تظهر السجلات في لوحة الحضور والانصراف

────────────────────────────────────────────────────────
👤  ربط مستخدمي ZKTeco بالنظام
────────────────────────────────────────────────────────

  كل مستخدم في نظامنا عنده حقل جديد:
    zkUserId: String

  لما تضيف موظف جديد في النظام، أدخل له:
    - رقم الموظف من جهاز ZKTeco (User ID)
    - هذا الرقم يخزّن في zkUserId

  bridge يرسل سجلات الحضور ومعها zkUserId
  السيرفر يبحث عن المستخدم اللي عنده نفس zkUserId
  وينشئ سجل الحضور باسمه وقسمه

────────────────────────────────────────────────────────
☁️  لما تنقل لسيرفر احترافي (VPS)
────────────────────────────────────────────────────────

  1. السيرفر الرئيسي يروح على VPS (مثلاً DigitalOcean, Hetzner,etc)
  2. bridge يضلّه في المكتب على جهاز كمبيوتر أو Raspberry Pi
  3. بس تغير API_BASE_URL في bridge/.env:

     API_BASE_URL=https://your-new-domain.com

  4. الباقي نفس ما هو. bridge يرسل HTTPS عادي للخادم الجديد.

────────────────────────────────────────────────────────
❌  المشاكل المحتملة والحلول
────────────────────────────────────────────────────────

  ❌ "فشل الاتصال بالجهاز"
    → تأكد أن IP الجهاز صحيح: ping 192.168.1.201
    → تأكد أن الجهاز على نفس الشبكة
    → تأكد أن فايروول ما يمنع port 4370
    → بعض أجهزة ZKTeco تحتاج TCP مش UDP

  ❌ "فشل إرسال السجلات للخادم"
    → تأكد أن الخادم الرئيسي شغال
    → تأكد أن API_BASE_URL صحيح
    → تأكد أن API_KEY متطابق في bridge و backend

  ❌ ما في سجلات جديدة رغم وجود بصمات
    → بعض أجهزة ZKTeco ما تمسح الذاكرة تلقائياً
    → احتاج تضيف أمر clearAttendance بعد القراءة
    → أو تحتاج تفعيل PUSH protocol من الجهاز نفسه

────────────────────────────────────────────────────────
🔧  أوامر مساعدة
────────────────────────────────────────────────────────

  تشغيل bridge:
    node bridge/index.js

  تشغيل bridge كخدمة ويندوز (PM2):
    npm install -g pm2
    pm2 start bridge/index.js --name zkteco-bridge
    pm2 save

  تشغيل bridge كخدمة لينكس (systemd):
    [Unit]
    Description=ZKTeco Bridge
    After=network.target
    [Service]
    ExecStart=/usr/bin/node /path/to/bridge/index.js
    Restart=always
    [Install]
    WantedBy=multi-user.target
