١. طلب نسيان بصمة (Fingerprint Forgotten)
------------------------------------------
أضفت type جديد في الإجازات اسمه fingerprint_forgotten يشمل:
- fingerprintType: نوع البصمة (دخول / خروج)
- fingerprintDate: تاريخ البصمة
- fingerprintTime: وقت البصمة (اختياري، افتراضي 08:00 للدخول و 16:00 للخروج)

أ. في Backend (backend/controllers/leaveController.js):
   - أضفت fingerprint_forgotten إلى LeaveType enum في نموذج LeaveRequest
   - عدلت createLeaveRequest لاستقبال fingerprintType, fingerprintDate, fingerprintTime
   - في approveWithPayrollSync:
     * عند الموافقة على طلب نسيان بصمة، يتم إنشاء أو تحديث سجل حضور في جدول Attendance
     * date = dayStart (منتصف الليل بالتوقيت المحلي) — متوافق مع طريقة zktecoController
     * checkIn.time أو checkOut.time = الوقت الذي أدخله المستخدم
     * status = present
   - أضفت دالة injectFingerprintToDevice():
     * تحاول إدخال البصمة إلى جهاز ZKTeco عبر node-zklib executeCmd(CMD_DATA_WRRQ)
     * تستخدم buffer بحجم 40 بايت (نفس تنسيق decodeRecordData40)
     * غير مانعة للتنفيذ (non-blocking) — لو فشلت، يتم تسجيل الخطأ فقط
   - أصلحت مشكلة:
     * leaveRequest.days = 1 كان داخل else فقط بدون save
     * الآن هو خارج if/else مع await leaveRequest.save()

ب. في Frontend:
   - Employee/LeaveRequest.jsx: أضفت فورم لاختيار fingerprintType (راديو), fingerprintDate (date picker), fingerprintTime
   - Manager/ApproveLeaves.jsx: أضفت عرض fingerprintType, fingerprintDate, fingerprintTime
   - Admin/GMApproveLeaves.jsx: نفس الإضافة
   - Admin/LeaveManagement.jsx: أضفت أعمدة للجدول وللـ chart

٣. ربط جهاز البصمة عبر SDK الرسمي
------------------------------------
المجلد SDK/ كان موجوداً ولكن غير مستخدم. يحتوي على zkemkeeper.dll وهي مكتبة ZKTeco الرسمية (COM).
المشروع كان يستخدم فقط node-zklib (مكتبة JavaScript بحتة) مما يسبب مشاكل في:
- عدم القدرة على كتابة سجلات للجهاز (للبصمة المنسية)
- عدم استخدام البروتوكول الرسمي

ما تم عمله:
أ. SDK/SDKBridge/SDKBridge.ps1 (ملف جديد):
   - PowerShell wrapper يستخدم zkemkeeper.dll عن طريق COM
   - يعمل فقط على 32-bit PowerShell لأن الـ DLL 32-bit
   - يستمع على TCP port 3457
   - الأوامر المدعومة: connect, disconnect, ping, status, info, get-all-attendance, inject-attendance

ب. bridge/index.js (تحديث شامل):
   - يشتغل SDKBridge.ps1 كعملية تابعة (child process) عند بدء الخدمة
   - يعيد تشغيله تلقائياً لو انهار
   - معمارية مزدوجة:
     * قراءة الحضور: node-zklib (أساسي لأنه أسرع ويدعم cursor) ← SDK Bridge (احتياطي)
     * معلومات الجهاز: SDK Bridge (أساسي لأنه موثوق) ← node-zklib (احتياطي)
     * كتابة البصمة: node-zklib executeCmd (أساسي) ← SDK Bridge (تجريبي)

ج. SDK/SDKBridge/SDKBridge.ps1:
   - تم إنشاء ملف PowerShell للتواصل مع zkemkeeper.dll
   - يعمل على 32-bit PowerShell (SysWOW64)
   - يتواصل مع Node.js عبر TCP
