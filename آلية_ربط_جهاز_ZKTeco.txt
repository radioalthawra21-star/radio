2. البروتوكول المستخدم
---------------------

  - البروتوكول: UDP/TCP (مكتبة node-zklib)
  - المنفذ الافتراضي للجهاز: 4370
  - المكتبة المستخدمة: node-zklib (v1.0.0+)
  - تم تثبيتها في:
    • bridge/package.json
    • backend/package.json


3. هيكل قاعدة البيانات
---------------------

  أ. نموذج User (models/User.js):
     ────────────────────────────
     {
       _id: ObjectId,
       name: "أحمد علي",
       email: "ahmed@example.com",
       department: "الأخبار",
       zkUserId: "123"        // ← معرف المستخدم في جهاز البصمة
       // ... باقي الحقول
     }

     مهم: الحقل zkUserId هو حلقة الوصل بين الموظف في النظام وبصمته على الجهاز.
     يتم ربط الموظفين عبر لوحة التحكم ← تعديل الموظف ← إضافة معرف البصمة.

  ب. نموذج Attendance (models/Attendance.js):
     ─────────────────────────────────────────
     {
       _id: ObjectId,
       employee: ObjectId (ref: User),   // الموظف
       date: Date,                       // تاريخ التسجيل
       department: String,               // القسم (للتقارير السريعة)
       status: "present" | "absent" | "late" | "half_day" | "on_leave",
       checkIn: {
         time: Date,
         status: "on_time" | "late" | "very_late",
         location: String,
         notes: String
       },
       checkOut: {
         time: Date,
         location: String,
         notes: String
       },
       duration: Number,     // عدد ساعات العمل
       overtime: Number,     // ساعات إضافية
       expectedHours: Number // الساعات المتوقعة (افتراضي 8)
     }

     فهرس فريد: { employee: 1, date: -1 } ← يمنع تكرار تسجيل لنفس الموظف في نفس اليوم


4. خيارات الربط (طريقتان)
------------------------

  الخيار الأول: Bridge Service (مستقل) - موصى به للإنتاج
  ──────────────────────────────────────────────────────

    الموقع: bridge/
    التشغيل: cd bridge && npm start
    يعمل كـ: عملية Node.js منفصلة

    المزايا:
    • لا يؤثر على أداء الخادم الرئيسي
    • يمكن تشغيله على جهاز منفصل بجانب جهاز البصمة
    • مزامنة دورية تلقائية (كل 30 ثانية)
    • إعادة اتصال تلقائي عند انقطاع الشبكة
    • آمن عبر مفتاح API (x-bridge-key)

  الخيار الثاني: ZKTeco Service (مباشر من الخادم)
  ───────────────────────────────────────────────

    الموقع: backend/services/zktecoService.js
    الاستخدام: POST /api/zkteco/sync (يتطلب صلاحية admin)
    API Endpoints المتاحة:
      • GET  /api/zkteco/status          - حالة الاتصال
      • POST /api/zkteco/sync            - مزامنة يدوية
      • GET  /api/zkteco/test-connection  - اختبار اتصال
      • GET  /api/zkteco/device-users     - جلب مستخدمي الجهاز
      • POST /api/zkteco/attendance       (للـ Bridge فقط - محمي بمفتاح)


5. سير عمل تسجيل البصمة (خطوة بخطوة)
-----------------------------------

  1. الموظف يضع بصمته على جهاز ZKTeco
  2. Bridge Service يقرأ السجلات من الجهاز عبر node-zklib
  3. Bridge يحول السجلات إلى JSON ويرسلها إلى:
       POST /api/zkteco/attendance
       Header: x-bridge-key: my-secret-key
       Body: {
         records: [
           {
             zkUserId: "123",
             zkRecordId: "456",
             timestamp: "2026-06-03T08:30:00",
             status: "present",
             verifyMode: 1
           }
         ],
         source: "bridge_192.168.1.201"
       }

  4. ZKTeco Controller يستقبل الطلب:
     أ. يتحقق من مفتاح Bridge
     ب. يبحث عن الموظف المرتبط بـ zkUserId في جدول User
     ج. يحدد نطاق اليوم (من 00:00:00 إلى 23:59:59)
     د. يبحث عن سجل حضور موجود لنفس الموظف + اليوم
     ه. منطق التسجيل:

        │ هل يوجد سجل؟ │
        ├──────┬───────┤
        │  لا  │  نعم  │
        │      │       │
        ▼      ▼       ▼
     إنشاء    │ هل لديه │
     سجل      │ checkIn │
     جديد     ├──┬──┬──┤
     (حضور)   │لا│  │نعم│
              ▼  │  │  │
          تحديث  │  │  │
          checkIn│  │  │
                 │  ▼  │
                 │ هل  │
                 │لديه │
                 │check│
                 │Out? │
                 ├─┬───┤
                 │لا│  │نعم│
                 ▼  │     ▼
             تحديث  │  تجاهل
             checkOut│  (مكرر)
             وحساب  │
             المدة  │
                    │
                    ▼
              تجاهل (نفس
              التوقيت ±60ث)

  5. يتم حفظ السجل في MongoDB
  6. يتم إرجاع رد للـ Bridge يتضمن:
     - عدد السجلات المحفوظة
     - التحديثات (حضور جديد / انصراف جديد / مكرر)
     - الأخطاء إن وجدت


6. آلية منع التكرار
------------------

  أ. على مستوى الـ Bridge:
     • يحتفظ بـ Set من المعرفات المُرسلة سابقاً
     • لا يرسل نفس السجل مرتين

  ب. على مستوى الـ Controller:
     • Set داخلي بمفتاح: employeeId_date_zkRecordId
     • فهرس فريد في MongoDB: { employee: 1, date: -1 }
     • تجاهل السجلات إذا كان الفرق بين check-in و check-out أقل من 60 ثانية


7. المتغيرات البيئية المطلوبة
---------------------------

  أ. في backend/.env:
     ─────────────────
     ZK_IP=192.168.1.201          # IP جهاز البصمة
     ZK_PORT=4370                  # Port الجهاز
     ZK_TIMEOUT=5000               # مهلة الاتصال (مللي ثانية)
     ZK_POLL_INTERVAL=30000        # دورة المزامنة (مللي ثانية)
     BRIDGE_SECRET_KEY=my-secret-key  # مفتاح التوثيق للـ Bridge

  ب. في bridge/.env:
     ─────────────────
     ZK_IP=192.168.1.201
     ZK_PORT=4370
     ZK_TIMEOUT=5000
     API_BASE_URL=http://localhost:3000
     API_KEY=my-secret-key
     POLL_INTERVAL_MS=30000
     SYNC_ON_START=true


8. كيفية ربط الموظفين مع الجهاز
-----------------------------

  لكل موظف في النظام حقل zkUserId في نموذج User.
  هذا الحقل يجب أن يتطابق مع User ID الموجود في جهاز ZKTeco.

  الطريقة:
  1. ادخل إلى جهاز ZKTeco عبر برنامج ZKBio أو من شاشة الجهاز
  2. أضف المستخدمين بأرقام معرفات (User ID)
  3. في لوحة تحكم النظام:
     - اذهب إلى قائمة الموظفين
     - ابحث عن الموظف
     - املأ حقل "معرف جهاز البصمة" بنفس الرقم الموجود في ZKTeco


9. استكشاف الأخطاء وإصلاحها
--------------------------

  ❌ "فشل الاتصال بالجهاز"
     → تأكد من أن IP الجهاز صحيح
     → تأكد من أن الجهاز متصل على نفس الشبكة
     → تأكد من أن المنفذ 4370 مفتوح
     → جرب ping على IP الجهاز

  ❌ "لا يوجد موظف مرتبط بهذا المعرف"
     → تأكد من أن zkUserId مضبوط في الملف الشخصي للموظف
     → تأكد من تطابق الرقم مع المعرف في جهاز البصمة

  ❌ "مفتاح bridge غير صحيح"
     → تأكد من تطابق BRIDGE_SECRET_KEY في backend/.env و API_KEY في bridge/.env

  ❌ المزامنة لا تعمل
     → تحقق من أن الخادم الرئيسي يعمل (http://localhost:3000)
     → تحقق من سجلات الـ Bridge (bridge/bridge.log أو stdout)
